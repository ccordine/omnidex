# Charmander autonomy proof ledger

Date: 2026-07-29  
Status: **not yet proven**

## Honest result

No current Charmander run is being claimed as proof that Omnidex can build an unfamiliar application from an ordinary request.

Earlier Go CLI runs are invalid as autonomy evidence for the current goal. They used registered application shapes and deterministic product adapters, invoked zero fragment workers, and therefore measured adapter rendering rather than general construction. Their generated projects and historical measurements must not be cited as proof of Omnidex autonomy.

The dependent simulation integration proves a narrow API integration and deterministic simulation boundary. It does not prove that Omnidex built that project.

## Foundation verified so far

The following checks establish framework primitives only:

* Go tests pass for portable jobs, complete raw-leaf semantic correction, AST parsing, context budgets, capability graph projection, worker routing, skill lifecycle, and workspace reconciliation.
* The generated generic browser substrate passes its real pinned Node install, Vitest suite, TypeScript type check, and Vite production build.
* That Node test caught and then guarded a real runtime defect where action status changed but state was never published.
* A historical live-core run established its then-current PostgreSQL registry and
  reported the exact active/bootstrap counts. That bootstrap path has since been
  replaced by the single destructive fresh-database setup and is not a current
  startup contract.
* Live PostgreSQL integration tests prove immutable bootstrap versioning, required learned-skill checks, immutable embeddings, activation, exact reuse, and bounded semantic retrieval.
* A live PostgreSQL integration test proves exact prompt and raw-response preservation, request/response hashing, partial failed-output preservation, bounded evidence pagination, and rejection of evidence updates or deletes.
* The running core, PostgreSQL, and Redis containers remain healthy after those checks.

None of these statements implies that a raw application request currently completes.

## Invalidated evidence removed from consideration

Do not count:

* deterministic habit-ledger, unit-converter, or expense-dashboard adapters;
* any workspace Codex edited directly;
* any run given a Codex-authored feature list, decomposition, rubric, source hint, or repair instruction;
* any run resumed after the framework was changed;
* any application-specific helper added to Omnidex after observing a benchmark failure;
* a static blueprint unit test as evidence that semantic interpretation produced that blueprint.

## Required proof run

Before a run starts, record:

* immutable source revision or tree digest;
* successful execution of the authoritative fresh-database setup against an empty
  runtime schema;
* exact model routing and embedding identity;
* fresh workspace identity and initial inventory;
* exact user request digest;
* zero human interventions.

During the run, append immutable evidence for:

* every portable job ID and kind;
* exact rendered prompt bytes and raw response contract;
* exact response bytes;
* every rejection and direct correction;
* every accepted AST declaration and content hash;
* skill candidates, checks, activation, rejection, and reuse;
* capability-relation decisions and resulting code-owned graph;
* staging and authoritative commands with output, duration, and exit status;
* workspace writes, protected-file reconciliation, final inventory, and stop reason.

After Omnidex stops, a separate observer may evaluate user-visible behavior. The builder must not see that rubric during construction.

## Acceptance sequence

The first counted sequence will use three materially different, fresh junior-application requests. Each request enters unchanged and each run proceeds without intervention. A framework change between attempts invalidates the current workspace and requires a new run from empty state.

For every run, report:

* completed, partial, or failed;
* capabilities demonstrably working and missing;
* stopping failure;
* model calls by station and model;
* total and maximum prompt bytes;
* corrections and retained work;
* verification commands and duration;
* files produced;
* human interventions;
* comparison with the Venusaur negative baseline.

This ledger changes to **proven for the measured scope** only after those artifacts exist. Until then, the correct answer to “is Omnidex usable as an autonomous builder?” is: **the foundation is materially stronger, but autonomy has not yet been demonstrated.**
