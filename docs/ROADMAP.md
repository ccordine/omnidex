# Roadmap

The target is functional, verified completion of the user's current objective
through code-owned workflow and narrowly bounded semantic calls. Hash receipts,
review activity, and preserved internal history are not completion measures.

## Immediate priority: reliable Linux functional completion

The current Linux `omni chat` path has produced a working Go command-line
application, verified independently after publication with ASCII, Unicode,
empty text, and terminal execution. The latest run completed in 293.518 seconds
and passed 15 recorded verification commands. Its three body calls received
327–370 bytes each. Code owns input-channel projection, typed results, output
formatting, test comparisons, and publication. A separate evaluator confirmed
that the comparison rejects a changed observed value.

The observed Linux stoppers in this diagnostic are resolved. The proven scope is
a small Go command-line application with scalar or text values. Broader workloads,
existing-project mutation, and post-compiler semantic correction remain to be
qualified through subsequent objectives. Cross-platform expansion and unrelated
hardening remain deferred.
See [the measured Linux result](CHARMANDER_PROOF.md#linux-minimal-context-diagnostic--verified-2026-09-13).

## Verified framework foundations

- One current internal database setup; service startup recreates its dedicated
  schema rather than migrating or preserving earlier internal state.
- Records of actual model calls, verification commands, database reads, and web
  acquisitions, with job-owned retrieval and citation checks.
- Exact-value simulation preparation, narrative freshness, atomic publication,
  and replay without repeated effects or content fingerprints.
- Fresh bounded workspace/map displays without persistent index files or hashed
  workspace identities.
- Workspace-local technical package names independent of host directory names,
  with product titles preserved separately.
- Progressive publication of complete verified task artifacts through the existing
  workspace reconciler, with earlier files retained across independent failures.
- Docker compilation and behavioral verification for all five registered stacks,
  with retained experiment files, exact process evidence, and container cleanup.
- Bounded dependency acquisition for the registered browser stack, followed by
  verified network disconnection before application source and commands enter.
- CLI builds for Linux amd64, macOS arm64, and Windows amd64 with C dependencies
  disabled. Shared session types live in the model package; the CLI dependency
  graph excludes server persistence, language parsers, and test helpers.
- CLI workspace attestation through its live client connection. Bootstrap,
  history, and ordinary turn intake work without a shared server mount, retain
  the same channel after reconnect, and reject replaced or disconnected roots.
  Client installation identities distinguish equal filesystem numbers on
  different machines; PostgreSQL accepts canonical native Windows and Unix paths.
- The CLI realtime stream survives successful bootstrap request completion.
- The CLI retains its invoking directory before configuration and network setup.
  Worker reads and verified publication use that retained directory through the
  same live connection. Bounded binary transfer, edit preconditions, partial
  publication, lock release, and Docker verification of client files have
  constructed integration coverage on Linux.

The scope and limitations of these tests are recorded in
[EVIDENCE_LEDGER.md](EVIDENCE_LEDGER.md) and
[CHARMANDER_PROOF.md](CHARMANDER_PROOF.md). Passing framework tests does not
establish autonomous construction of an unfamiliar application.

## Remaining work

- Deferred: finish native macOS/Windows filesystem mutation adapters and verify
  directory, publication, and terminal behavior on those systems. The partial
  adapters are not evidence of native functionality.
- Generalize existing-project mutation and technical stack support beyond the
  current five registered application compilers.
- Generalize dependency acquisition and learned procedure/skill support beyond
  the registered compilers and browser dependency set.
- Resolve behavioral verification limits, including browser requirements whose
  derived results need an exact oracle the current adapter cannot construct.
- Finish auditing current semantic calls and their actual model-visible inputs
  against the one-unresolved-question boundary.
- Finish reconciling architectural documents with the actual current-value
  runtime contracts and measured implementation limits.
- Demonstrate the ordinary production request boundary through a fresh,
  unsteered build and evaluate its resulting user-visible behavior only after
  the build stops.

The former hash-backed index, command cache, failure-fingerprint, and local
ledger/trace CLI tracks are retired, not features to restore. Current CLI
entrypoints are `omni chat` and `omni version --json`; explicit API transports
own other supported operations.
